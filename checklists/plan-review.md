# plan-review — 審 Plan

## CHECK
- [ ] 接口/數據結構一致：與規格一字不差？無順手改名/加字段？
- [ ] 依賴方向：與架構一致？無反向？無循環？
- [ ] 假設清單：每條都認可？（一條錯 → 後面全偏）
- [ ] 範圍邊界：沒偷做沒要求的事？
- [ ] 不確定項：Plan 標的歧義都已明確答覆？
- [ ] 執行順序：骨架先行？主流程先於異常分支？
- [ ] 分流建議：A/B/C 合理？（對照 routing.md）
- [ ] （走A）接縫契約：子Goal間接口定死、標不可擅改？
- [ ] （走A）集成：增量、非大爆炸？

## ANTI-PATTERN
- [ ] Plan 只把規格換句話說 → 無價值。追問「做了哪些假設？哪裡規格沒講清？」
- [ ] Plan 沒暴露任何假設/沒提任何問題 → Agent 多半偷懶，逼它說。

## PASS
- [ ] 全過 → 放行執行
- [ ] 任一不過 → 修正後重審
