# 05 — 驗收 → /goal 完成條件

CORE: /goal 驗證者（Haiku）讀 transcript 判定 → 條件 MUST 綁「可執行命令的 true/false 輸出」。 → R2

## /goal 骨架（cp 改用）
```
/goal --tokens [上限如200K] 完成本任務，達成條件（全部滿足才算完成）：

[成功條件 — 每條綁命令輸出/退出碼]
1. `pytest tests/ -q` 退出碼 0，且 [具體測試] 全綠
2. `coverage report` 中 [模塊].py ≥ [N]%
3. 模擬 [失敗場景] N 次成功率 100%（見 [test文件] 輸出）
4. `git diff --name-only` 不含 [禁區路徑]
5. 連續運行測試 3 次結果一致
N. 產出 HANDOFF.md，含 WHAT/WHY/TRAPS/接口契約/可執行驗收命令 五區塊且非空

[失敗熔斷 — 達成任一則停止並報告，不再嘗試]
- 同一測試連續 3 輪失敗且錯誤相同（卡死）
- 遇規格未覆蓋的決策分叉（需人定方向）
- 需動禁區（schema/權限/外部系統）
- 連續 2 輪無實質代碼進展

[人類介入信號 — 遇到停下等人]
- 範圍超出原 Plan
- 借鏡與規格衝突，不知誰優先
- 任何涉及權限/外發/刪除

max [N] turns。
每完成一輪 MUST 貼實際命令輸出作為證據，不要只說「已通過」。
若涉及 UI/可視產物，MUST 附截圖或可點預覽路徑，不要只用文字描述界面。 → R8
```

## 轉換 RULE
- 每條完成條件 = 跑1命令 + 看輸出/退出碼 → true/false。MUST NOT 靠閱讀判定。
- ❌「功能正常」 → ✅「`pytest -q` 退出碼 0」
- ❌「通訊穩定」 → ✅「斷線100次重連成功率100%，無未捕獲異常」
- 「請貼真實命令輸出」MUST 加：給驗證者可讀 + 讓人事後抽查看真輸出。
