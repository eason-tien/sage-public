# 03 — Plan 契約 + 分流

VALUE: Plan 價值在「審查」非「生成」——攤開 Agent 隱性理解讓人核對。
TASK: 進 Plan 模式。基於【01 規格】+【02 借鏡】輸出執行計劃。

## MUST
- 先輸出計劃，MUST NOT 寫任何實際代碼。
- 計劃 MUST 列：
  1. 改哪些/新增哪些文件（路徑 + 一句話職責）
  2. 模塊依賴方向（與架構一致，無反向）
  3. 執行順序（骨架先行，主流程先於異常分支）
  4. 對規格做的所有假設（人逐條確認）
  5. 有歧義/不確定處（標出問人）
- FAIL IF 計劃只把規格換句話說。好計劃 MUST 比規格多信息：具體怎麼做到 + 暴露假設與問題。

## ROUTE 建議（Agent 提建議，人拍板） → routing.md
| 定位 | 適用 |
|---|---|
| A 人主導拆分+接縫契約+HANDOFF | 核心/高風險/需接力/需嚴格接縫 |
| B UltraCode 並行探索 | 廣度：調研/審legacy/遷移評估 |
| C UltraCode 全自動 | 一次性/獨立/無接手/不需嚴格接縫 |

DECIDE:「之後有別的 Agent 接手嗎？需嚴格控接縫嗎？」都否→可C；任一是→必A；純廣度→B；拿不準→A。

## IF 走A，MUST 同時
- 拆成有依賴順序的子 Goal（A→B→C），每個用 5-10 條可驗證斷言講清。
- 定義子 Goal 間接縫契約（接口簽名+輸入輸出），寫進各子 Goal 規格，標「不可擅改，改須人確認」。 → CONTRACT.md
- 規劃增量集成（A綠→合→B…），MUST NOT 大爆炸集成。

GATE: 人確認 計劃+分流+接縫契約 後才進執行。
