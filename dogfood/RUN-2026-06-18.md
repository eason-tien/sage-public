## 任务
把「ai-dev-sop 自身可用」当一个真实任务，用它**自己的 R9 闭环**（锁定验收集 → 亲跑 verify）验证。

## 可机械验收（`dogfood/acceptance.txt`，已锁定）
```

```
（selftest 本身是 16 条机械检查：new-task / verify / acceptance-lock / crosscheck，全部按退出码判。）

## Lessons（本轮真实摩擦，反向优化上游）
1. **Workflow 的 `args` 以 JSON 字符串送达**，不是对象——`sop-run.js` 没 `JSON.parse` 时空规格跑、agent 全体 hard-stop。已修。（[[workflow-args-json-string]]）
2. **`.ps1` 的 BOM**：用 Edit 改既有 .ps1 会保住 BOM；新建 .ps1 用 Write 不带 BOM，故 `acceptance-lock.ps1` 写成 **ASCII-only** 规避乱码。
3. **空规格那次反而是最强证明**：agent 没编造规格，按 H2/P1 硬停退回出题者——内核纪律在真实自动化里站住了。
4. **形态2（自动编排）是有意识的 opt-in 放宽**（NON-GOAL #1），默认仍形态1；写进 DESIGN/CHANGELOG，不让它悄悄漂移。
5. **跨平台 sha256 大小写不同**（PowerShell 大写 vs `sha256sum` 小写）→ 统一转小写，锁才可移植。

## 发现并当场修复的边界（这才是 dogfood 的价值）
- **R9 锁原本 hash 原始字节** → git EOL 规范化（CRLF↔LF）跨机 checkout 会让哈希变 → `verify` 误报 TAMPERED。
- **已修**：`acceptance-lock`（PS/bash）哈希前先 CRLF→LF 归一化；`verify` 改为委派 `acceptance-lock check`（哈希逻辑只存一处，DRY）。
- **重验**：两平台 selftest 重跑仍 16/0；dogfood 重锁后 `verify` 仍 exit 0。
- 一句话：**真用一次，挖出一个真 bug，当场按机械验收修掉**——dogfood 不是仪式，是它该干的事。
